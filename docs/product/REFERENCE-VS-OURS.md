# Reference vs AutoAPPZ — Competitive Improvement Report

Every "Expected improvement" names how it will be measured; nothing here is claimed as achieved until the linked test/benchmark exists and passes.

| Capability | Reference approach | Limitation | Our approach | Expected improvement | Evidence / test |
|---|---|---|---|---|---|
| **Architecture** | One `src/` tree for main/renderer; 170k-line main monolith; flat `utils/`; convention-enforced boundaries | Cross-layer coupling, FSL types leaking to renderer, 3.5k-line handlers | Monorepo packages with lint-enforced layering; renderer depends only on `contracts`+`ui` | Boundary violations = 0 in CI; largest module < 800 lines | ESLint boundaries rule in CI; `tools/check-package-sizes` |
| **Code intelligence** | In-memory TS-program graph, TS-only, non-incremental, serialized with tsc; vendor smart context | Cold rebuilds, blind to CSS/config/docs, no persistence | Persistent incremental index (tree-sitter + FTS5 + graph), hybrid retrieval with explanations | Recall@30k ≥ 0.9 on retrieval benchmark; incremental reindex < 100 ms | `tests/evals/retrieval`, BENCHMARKS.md |
| **Agent planning** | Prompted workflow steps; blueprint (name/color/design/visuals) in memory; plan mode writes markdown | No task lifecycle, no criteria, blueprint lost on restart, shallow scope | Persisted task state machine; structured Blueprint (pages/entities/roles/auth/API/tests/AC); Planner expands "complete app" scope | Full-app eval: ≥ 80% of scope checklist items present on first run | `tests/evals/full-app` restaurant suite |
| **Execution** | Native tool loop (FSL); search_replace line-based; no changed-since-read | Silent overwrites possible; mangled edits | Read-before-write, hash-checked patches, AST-aware edits where available, diff preview | 0 silent overwrites in conflict tests; patch failure rate < 2% on edit eval | `packages/tools` conflict tests; edit eval |
| **Repair loops** | User-triggered "Fix error"; model may run tsc/tests; no post-turn validation | Broken builds ship; repair unbounded/ad hoc | Mandatory cheapest-first validation; structured diagnostics; bounded repair (3) | ≥ 95% recovery on injected-error suite | `tests/evals/repair` |
| **Git** | Commit per turn; revert/restore-to-message; `[Interrupted]` checkpoint in some paths | Dirty-tree handling inconsistent; metadata decoupled from repo | Checkpoint refs capturing user changes before tasks; undo/restore/compare/branch-from; trailers | Property test: undo never loses user edits (100%) | `packages/git` property tests |
| **Context management** | Turn-limited history + compaction; token estimate chars/4 | Imprecise budgets; provider caps hard-coded | Tokenizer-aware budgets per source; explainable packs; compaction with memory extraction | Budget overruns = 0 in evals; cost per task −30% vs dump baseline | eval cost report |
| **Permissions** | Per-tool `ask/always/never`; SQL/MCP classifiers | Coarse; no scope; no audit log | Capability+scope+risk policies; once/session/project; audit per call | 100% privileged tools audited (test) | `packages/permissions` tests |
| **Runtime** | `install && dev` shell string; stdout-regex readiness; kill-port; 3 modes in one service | Opaque failures; foreign process kills; hung servers "ready" | Runtime Supervisor with phases, port leases, health probes, structured events | Startup failure attribution 100% (phase named); 0 foreign kills | runtime integration tests |
| **Deployment** | Vercel + experimental Coolify; no readiness checklist | Deploy is a side panel | Deployment adapters + readiness checklist (env, migrations, build, tests) | Deploy eval passes for Vercel/Netlify/Cloudflare/Docker templates | `tests/e2e/deploy` (mocked APIs) |
| **Testing** | Strong e2e/hybrid harness; agent flows skipped on Windows; no coverage; no migration tests | Platform gaps, brittle snapshots | Deterministic integration/E2E on 3 OSes; coverage gates; migration upgrade tests; evals | CI green on ubuntu/windows/macos; coverage ≥ 80% core packages | CI |
| **Recoverability** | Durable intents/queues; interrupted sub-agents reconciled | Task-level resume absent | Task journal; resume into VALIDATE; NEEDS_USER with options | Crash-resume test passes | `packages/core` recovery tests |
| **Extension system** | MCP + curated catalog; no plugin SDK | Only MCP | Plugin SDK with capability manifests; adapters for providers/deployers/DBs/templates/validators | Sample plugin passes SDK compatibility suite | `packages/plugins` tests |
| **UX** | Chat with 4 modes + 10 preview modes; integrations in 3 places; ~60 settings | Cognitive load; funnel-first onboarding | Workspace (Request/Plan/Execution/Changes/Validation + dock); one agent; integrations hub; BYOK-first | Task-completion time on usability script −40% (measured with 5 users) | usability protocol in `docs/product/USER-FLOWS.md` |
| **Performance** | No benchmarks published; single validation lane | Unknown | Benchmarks for startup, index, open, first token, retrieval, preview start, build, memory | Targets in BENCHMARKS.md | `tools/bench` |
| **Observability** | electron-log + PostHog + debug bundle | Ids not correlated across task/tool/process | Structured logs with `sessionId/projectId/taskId/agentRunId/toolCallId/processId`; redacted bundles | Every log line carries ids (lint) | diagnostics tests |
| **Security** | Hardened Electron; secrets to renderer; unvalidated legacy handlers; no CSP | S1–S10 findings | Secrets by reference; all IPC validated; CSP; sandbox true; scoped permissions | 0 secret leaks in renderer payload tests; CSP enforced | security test suite |

## Methodology notes
- Evals run nightly on fixture projects with recorded/fake model responses for determinism, plus a weekly live-model run with fixed seeds where supported; results are stored as JSON and trended.
- Usability metric requires human sessions; until then, the proxy metric is the number of UI actions required for the 14-step vertical slice (target ≤ 8 user actions after the prompt).
