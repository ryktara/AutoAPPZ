# ADR-003: Platform database and project state

**Status:** Accepted · **Date:** 2026-09-16

## Context
The platform needs a local catalog (projects, sessions, tasks, checkpoints, audit, usage, memory) and per-project indexes; the user's repository must stay clean and portable.

## Decision
- **SQLite via `better-sqlite3` + Drizzle ORM** for the platform database at `<userData>/autoappz.db` (WAL, foreign keys); migrations generated by drizzle-kit, applied at startup with a pre-migration backup and a verified rollback path.
- Task journal (`task_events`) and audit (`tool_calls`) are append-only tables.
- **Per-project index DB** at `<userData>/projects/<projectId>/index.db` (owned by the Context Engine), rebuildable.
- Settings in the same DB (`settings` table, typed), **secrets only as references** to the secrets service.
- Nothing is written into the user's repo except optional standard instruction files the user creates; platform caches, if any, are excluded via `.git/info/exclude`.
- Integration bindings are rows in `integrations {projectId, kind, adapterId, config(json), status}` rather than columns on `projects`.

## Alternatives
JSON files (no transactions/queries), PGlite (heavier), LevelDB (no SQL).

## Consequences
Schema evolution via migrations with upgrade tests against fixture databases from previous releases.

## Migration impact
None.
